воспроизведения; правки раннера, main и production запрещены).

   `ObjectInUse` на DROP, **exit=1** — состояние «до».

   каждая утечка завершается по метке запуска; `logs/full-suite-1/2.log` —

3. **Реальная серверная метка** — `logs/label-capture.log`: 18 сессий

   вердикт).

## Воспроизведение

`reproduce.md` — команды каждого evidence-пункта. Все прогоны выполняются
на изолированных тестовых БД (`test_*`), чужие БД не затрагиваются.

## Обезличивание

Досье обезличено для передачи независимому аудитору: имена БД и
пользователя тестового окружения, локальные пути стенда и пароли заменены
на плейсхолдеры (`<project_db_user>`, `<test_db>`, `<project>`, `<venv>`,
`<local_password>` и т.п.). Инструменты читают учётные данные только из
переменных окружения (`PGUSER`/`PGPASSWORD`, `DB_USER`/`DB_PASSWORD`) —
в файлах их нет. Полный замена-скан перед коммитом: 0 совпадений.

## Границы

- Первопричина утечки — **устранена на уровне теста**: async-тест
  переписан (agent/async-epoch-test-rewrite, 7af0dca + 3e000bb), квартет
  на базе ff296f9 БЕЗ дренажа — 4/4 exit=0, 0 утечек. Дренаж остаётся
  страховкой гонки close→DROP и будущих утечек.
- Метка `application_name` — идентификатор запуска, **не удостоверение
  владельца**; для строгой модели угроз требуется отдельное решение.
- Дефекты раннера (отчёт дренажа, boolean terminate, scope метки) —
  исправлены в ветке agent/runner-report-fixes (aed2116b) и ждут слияния.
- Семантика ContextVar зафиксирована для asgiref 3.13.0 + Python 3.14;
  при обновлении asgiref ожидание теста перенастроить.
