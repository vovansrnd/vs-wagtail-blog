# Д68-Т / teardown-hygiene — аудиторское досье

**Ветка:** `agent/teardown-audit-dossier` (документация, логи и инструменты
воспроизведения; правки раннера, main и production запрещены).
**Предмет:** два результата программы teardown — решённая практически
очистка тестовых БД (PR №4, `main@22926cee`) и неустранённая первопричина
утечки соединения.

## Состав

| Файл | Что это |

## Ключевые факты (по логам)

1. **База `ff296f9` (без дренажа)** — `logs/base-ff296f9-quartet.log`:
   24 теста OK, утечка поймана диагностикой
   (`foreign session pid=564149 idle, last_query=SELECT … blog_invalidationepoch`),
   `ObjectInUse` на DROP, **exit=1** — состояние «до».
2. **`main@22926cee` (дренаж)** — `logs/quartet-*.log`: **15/15 exit=0**,
   каждая утечка завершается по метке запуска; `logs/full-suite-1/2.log` —
   **159 тестов, OK, 4 skipped, exit=0 ×2**.
3. **Реальная серверная метка** — `logs/label-capture.log`: 18 сессий
   прогона, все `application_name='vs-wagtail-tests-565391-5a203f24'`.
4. **Точка утечки** — `logs/threads-trace.log`: соединение открывается
   внутри `test_async_asend_resets_cache` (после `asend`), два
   MainThread-коннекта `default` живы одновременно, утечка не закрывается
   до выхода процесса.
5. **Чужая сессия** — `logs/no-label-foreign-scenario.log`,
   `logs/parallel-run-A/B.log`, `logs/boundary-regression-test.log`:
   сессии без метки запуска (параллельный запуск, диагностика) не
   завершаются дренажем; DROP при чужой сессии честно падает с
   `ObjectInUse` (exit=1 — правильный исход).
6. **Дефекты раннера** — `logs/drain-report-gap-demo.log`
   (terminate-результат не проверяется; «DROP без гонки» при живой сессии),
   `logs/dead-pg-demo.log` (отказ служебного подключения не маскирует
   вердикт).

## Воспроизведение

`reproduce.md` — команды каждого evidence-пункта. Все прогоны выполняются
на изолированных тестовых БД (`test_*`), чужие БД не затрагиваются.

## Границы

- Первопричина утечки (Django/asgiref × `CONN_MAX_AGE=0` × async) —
  **не устранена**, локализована; дренаж — страховка, а не исправление.
- Метка `application_name` — идентификатор запуска, **не удостоверение
  владельца**; для строгой модели угроз требуется отдельное решение.
- Дефекты раннера (отчёт дренажа, boolean terminate, scope метки) —
  задокументированы, ждут отдельного исправляющего PR.
